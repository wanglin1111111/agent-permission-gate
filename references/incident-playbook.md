# 事件 Playbook：被拒、告警、泄露、沉淀

## 被拒请求判读

拒绝信息应能定位到 **程序 + 目的地（主机+端口）+ 凭据上下文**。判读流程：

```
被拒请求
  ├─ 程序+目的地在白名单外？ → 正常拦截，看是否该加规则（走补权限流程）
  ├─ 目的地正确但凭据端点不匹配 → credential_endpoint_mismatch
  │    处置：不是"放开网络"，而是把凭据的声明端点补齐/改对
  │         （批准访问 A ≠ 给 A 带密钥的能力；端点声明要跟着实际用途走）
  ├─ 目的地是私有地址？ → 警惕：默认不应放行内网探测，过 Policy Prover 再看
  └─ 高频同类拒绝？ → 说明白名单缺一段，起草最小规则（程序+主机+端口）批量补
```

**判读纪律**：每一次放行决策都记一行（观察日志），拒绝是权限画像的数据源，不是噪音。

## 静默放行告警处置（best_effort 陷阱）

文件策略为 best_effort 时，规则应用不了 → 沙箱照样跑 + 一条告警。处置：

1. **立即**：查告警对应哪条规则没生效（目录不存在？路径变了？权限模式？）
2. **当日**：把文件策略改成 `hard_requirement` 重跑验证——卡死才是锁
3. **复盘**：告警出现过的窗口期内，Agent 实际能碰到的范围比策略声明的宽，
   检查该窗口内 Agent 的写操作记录

## 密钥泄露轮换流程

触发条件（任一）：
- 密钥出现在项目文件 / 提示词 / 日志 / Agent 可读目录
- 密钥曾以真值（非占位令牌）进过 Agent 环境
- 无法确认密钥是否只走 Provider 通道

```
1. 立即在 Provider/源平台轮换（旧密钥失效）
2. 新密钥只进 Provider，声明端点
3. 搜一遍仓库/提示词模板/文档，清掉旧密钥残留
4. 在事件日志记：泄露面（哪些文件/提示词）+ 窗口期 + 已轮换
```

## 策略模板沉淀格式

团队推广时，把个人跑通的策略沉淀为可复用模板：

```markdown
# 策略模板：<仓库类型，如 前端 monorepo>
## 文件白名单
读: ...  写: ...  禁: .env/** secrets/** 系统目录
## 域名白名单
（包源 + 必需端点，逐条带用途注释）
## Provider 凭据表
（凭据名 / 声明端点 / 占位令牌名）
## 已知合理拒绝
（哪些拒绝是正常的，避免团队反复误放行）
## Policy Prover 结果
（模板级规则过一遍，标记的私有地址/通配主机处置记录）
```

## 上 K8s 前置检查

- 先确认集群网络插件**真的执行 NetworkPolicy**（测试：建一条 deny-all 策略看是否生效）
- 插件不执行 → 规则只是写在纸上，先换插件/配 CNI，再谈 Agent 策略
