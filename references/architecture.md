# 架构原理：权限锁怎么锁

## 问题：权限靠"信任"

Coding Agent 要读代码、改文件、装依赖、调 API，就得给它权限。给了权限，你无法保证它不读密钥、不连无关服务。写在提示词里的规矩没有执行力——模型可以"忘"、可以"被注入"、可以在长上下文里漂走。

**核心转变**：规则从提示词里的软要求，变成执行时的硬拦截。

## 分工：Agent 决定做什么，运行时决定能做到哪一步

```
Agent（思考 + 调工具，不变）
  │ 发起工具调用
  ▼
OpenShell（运行时，在"工具真正落地"的那一刻卡住它）
  ├─ 文件操作 → Landlock 裁决
  ├─ 网络请求 → 沙箱外 Supervisor 裁决
  └─ 凭据使用 → Proxy 替换 + 端点核对
```

Agent 继续思考、调工具；运行时负责拦截。提示词可以漂移，内核策略不会。

## 网络：裁决权在沙箱外

```
Agent（受限一侧）→ 请求先经沙箱 → 沙箱外 Supervisor 核对策略 → 通过才建立真实连接
```

关键设计是**隔离**：Agent 在自己的受限一侧，**没资格自证"这个请求安全"**——裁决者必须在被裁决者之外，否则等于让 Agent 给自己发通行证。

## 文件：能写 ≠ 写得对

- Linux 后端用 **Landlock** 限制目录读写，非 root、无 capabilities
- ⚠️ **文件策略默认 `best_effort`**：规则应用不了时沙箱照样跑，只记一条告警——**要卡死必须改成 `hard_requirement`**
- 语义区分：Landlock 管的是"越权"（能不能碰这个目录），不管"写错"（碰对了但改坏了）

## 密钥：给占位符，不给真钥匙

```
Provider（宿主机侧，托管真实凭据）
  │ Agent 环境里只有占位令牌
  ▼
Agent 用占位令牌发请求
  ▼
Proxy（转发前替换成真凭据）
  │ 端点核对：这个凭据只许发到声明过的端点
  ▼
真实目的地
```

- **能联网 ≠ 能带密钥**：两次独立检查。批准访问 A 网站，不等于把 GitHub Token 交给它
- 发错端点 → `credential_endpoint_mismatch` 拒绝
- 你手动塞进文件/提示词的密钥，Provider 管不了

## 补权限：拒绝 → 提案 → 人批准

```
Agent 装依赖被拦
  → 运行时从拦截记录起草最小规则（限定到程序+主机+端口）
  → 人在宿主机确认
  → 热加载生效，不用重启
```

Policy Advisor 可让 Agent 自己提案，但**默认关闭、默认等人工审核**。

## 校验：Policy Prover（SMT 求解器）

新增规则交给 Policy Prover 分析：
- 有没有"带着凭据访问新目的地"的能力
- 标记私有地址、通配主机

**注意边界**：只验证策略本身写得危险不危险，**不验证 Agent 写出的代码对不对**。

## 边界：它不是万能保险箱

| 不管的 | 原因 |
|---|---|
| 原始 TLS 隧道里的凭据 | 隧道加密，Proxy 看不到内容，不做凭据替换 |
| 你塞进文件/提示词的密钥 | 不走 Provider 通道的凭据不在管辖范围 |
| 云端推理的内容外发 | 请求批准后发给云端模型，内容照样到达模型服务商——**沙箱管的是权限，不是把云推理变本地推理** |
