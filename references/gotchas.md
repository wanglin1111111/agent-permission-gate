# 坑位清单

## best_effort 静默放行（最隐蔽）

**坑**：文件策略保持默认 best_effort，某条规则因路径变化没生效，沙箱照样跑，只有一条告警混在日志里。
**表现**：你以为锁着，其实没锁——Agent 碰到了策略声明之外的目录，且没有硬拒绝记录。
**对策**：接真实仓库前必须改 `hard_requirement`；告警当安全事件处理，不当噪音。

## 通配规则一口开到底

**坑**：白名单里写 `*.github.com`、`0.0.0.0/0`，图省事。
**问题**：通配主机/私有地址正是 Policy Prover 要标记的危险口子；"带凭据访问新目的地"的能力经常从通配里长出来。
**对策**：规则限定到程序+主机+端口；确需宽域名的，单独过 Policy Prover 并留处置记录。

## 自动批准图快

**坑**：嫌逐条确认烦，开自动批准或打开 Policy Advisor 自动生效。
**问题**：观察期没过，权限画像没有底；Agent 自提案自放行 = 裁决者与被裁决者合一，回到"求"。
**对策**：观察周期内保持人工审批；有底后再放开**不涉及凭据**的公网访问。

## 把沙箱当代码质量工具

**坑**：以为上了 OpenShell 就不用 code review / 测试 / git 审查了。
**问题**：沙箱管"越权"（能不能碰），不管"写错"（碰对了但改坏了）——开放的可写目录照样被改错。
**对策**：Agent 输出永远当草稿，工程纪律（审查/测试/版本管理）照常做。

## 能联网 ≈ 能带密钥

**坑**：批准了某域名的网络访问，默认凭据也能跟着发到那。
**问题**：两次独立检查；端点不匹配会被 credential_endpoint_mismatch 拒，但"能发"和"该发"是两回事。
**对策**：凭据声明端点跟实际用途走，一个凭据一个端点声明，不共用。

## 旧密钥留在仓库/提示词里

**坑**：密钥早出现在 README、提示词模板、脚本注释里，上了 Provider 但旧密钥没轮换。
**问题**：出现过即视为泄露——Agent 读得到文件，Provider 通道管不住文件里的真值。
**对策**：上 Provider 时同步轮换；搜干净残留；记事件日志。

## K8s NetworkPolicy 纸面规则

**坑**：策略模板搬上 K8s，NetworkPolicy 写了一堆，实际集群 CNI 根本不执行。
**问题**：规则只是写在纸上，放行了也不知道。
**对策**：先做 deny-all 测试确认插件执行，再搬策略。

## TLS 隧道凭据盲区

**坑**：Agent 走原始 TLS 隧道访问某服务，以为 Proxy 会替换凭据。
**问题**：隧道加密，Proxy 看不到内容，不做凭据替换——这条通道上的凭据是裸奔的。
**对策**：需要凭据替换的流量不走原始 TLS 隧道；或者该通道的凭据按"直接暴露给 Agent"评估风险。

## 云推理内容外发盲区

**坑**：以为沙箱把一切都锁住了，请求内容不会出宿主机。
**问题**：请求批准后发给云端模型，内容照样到达模型服务商——沙箱管的是权限，不是把云推理变本地推理。
**对策**：涉密代码/数据的任务，评估是否该换本地模型或做内容脱敏，别默认云推理安全。

## 裸奔进真实仓库 / 小脚本配保险箱

**坑（两个方向）**：让 Agent 碰真实代码库+密钥却没上任何运行时拦截；或者给独立小脚本配全套策略。
**对策**：决策点——碰真实仓库+密钥才值得半天成本；小脚本阶段收益不抵学习成本。
