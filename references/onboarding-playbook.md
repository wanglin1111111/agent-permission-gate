# 落地 Playbook：六步接入

## 第 1 步：决策点

| 你的现状 | 决策 |
|---|---|
| Agent 已在碰真实代码库、真实密钥 | **值得花半天跑通** |
| 还在让 Agent 写独立小脚本 | 收益不抵学习成本，先不接 |

## 第 2 步：空沙箱验证（别一上来接真实仓库）

官方三步：

```bash
# 1. 安装（按官方文档）
# 2. 确认状态
openshell status
# 期望：Status: Connected + Authentication: Authenticated
# 3. 建沙箱
sandbox create --name demo
```

- 默认镜像不带 Agent CLI，**空沙箱是正常的**
- 拿一个**无敏感数据**的小项目验证三件事：

```markdown
# 空沙箱验证清单
- [ ] 工具能不能跑（装依赖/跑构建/读文件）
- [ ] 网络规则够不够（该通的通了吗）
- [ ] 被拒的请求好不好判断（拒绝信息能否定位到 程序+目的地）
```

## 第 3 步：最小权限策略先行（不是事后补救）

接入日常仓库**前**，填完三张白名单：

```markdown
# 最小权限策略模板
## 读目录
- <repo>/src
- <repo>/tests
## 写目录
- <repo>/src（仅 Agent 负责改的部分）
- 禁止：<repo>/.env、<repo>/secrets/**、系统目录
## 域名
- <包管理器源>（装依赖）
- <必需的 API 端点>
## 文件策略模式
- hard_requirement   ← 必须，默认 best_effort 是静默放行陷阱
## 规则粒度
- 程序+主机+端口，不写通配
```

## 第 4 步：密钥全走 Provider

```markdown
# Provider 配置清单
| 凭据 | Provider 名称 | 声明端点 | 占位令牌名 |
|---|---|---|---|
| GitHub Token | github | api.github.com | GITHUB_TOKEN |
| 包管理令牌 | npm | registry.npmjs.org | NPM_TOKEN |
```

- 任何 API Key 都配进 Provider，Agent 只拿占位令牌
- **项目文件、提示词里出现过的旧密钥视为已泄露**，该轮换就轮换
- 这是收益最大、成本最低的一步

## 第 5 步：人工审批观察周期

- **别开自动批准**；Policy Advisor 保持默认关闭
- 先用小任务跑满一个观察周期，记录：

```markdown
# 权限观察日志
| 日期 | 被拒请求(程序+目的地) | 是否合理放行 | 备注 |
|---|---|---|---|
```

- 看到"具体哪个程序要访问哪里"，比"允许所有操作"好判断得多
- 对权限画像有底后，再考虑放开**不涉及凭据**的公网访问

## 第 6 步：团队推广顺序

```
个人先跑通
  → 沉淀可复用策略模板（文件白名单 + 域名白名单 + Provider 凭据）
  → 给团队的 Agent 统一套上
  → 上 K8s 前：先确认集群网络插件真的执行 NetworkPolicy（否则规则只是写在纸上）
```

## 持续纪律

- Agent 输出当**草稿**：代码审查、测试、版本管理该做的还得做
- 策略模板进版本管理：改动走评审，新增规则过 Policy Prover
