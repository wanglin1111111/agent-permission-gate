# OpenShell：给 AI Agent 用的带权限锁的工作间

> 源材料：OpenShell（安全私有运行时，Agent 权限治理）拆解
> 本文为 `agent-permission-gate` 技能的方法论底座；可执行工作流见 `../SKILL.md`。

## 一、奥卡姆剃刀下的主题

一句话：**OpenShell 就是一个"给 AI Agent 用的带权限锁的工作间"。**

剥掉"安全私有运行时""数据平面/控制平面""SMT 求解器"这些词，剩下的最小解释只有一句：**以前你只能"求"Agent 别乱来，现在你能"强制"它别乱来。**

规则从提示词里的软要求，变成了执行时的硬拦截。这就是全部主题，其余都是这句的实现细节。

## 二、核心提炼

### ① 问题：权限靠"信任"

Coding Agent 要读代码、改文件、装依赖、调 API，就得给它权限；给了权限，你无法保证它不读密钥、不连无关服务。写在提示词里的规矩，没有执行力。

### ② 解法：提示词管不住，就交给运行时

Agent 继续思考、调工具；OpenShell 负责在"工具真正落地"的那一刻卡住它。分工一句话：**Agent 决定做什么，OpenShell 决定能做到哪一步。**

### ③ 网络：裁决权在沙箱外

请求先经沙箱 → 由沙箱外的 Supervisor 核对策略 → 通过才建立真实连接。关键设计是隔离：Agent 在自己的受限一侧，没资格自证"这个请求安全"。

### ④ 文件：能写 ≠ 写得对

Linux 后端用 Landlock 限制目录读写，非 root、无 capabilities。但有个坑：**文件策略默认 best_effort，规则应用不了时沙箱照样跑，只记一条告警——要卡死就得改成 hard_requirement。**

### ⑤ 密钥：给占位符，不给真钥匙

Provider 托管真实凭据，Agent 环境里只有占位令牌，Proxy 转发前才替换。且"能联网"和"能带密钥"是两次独立检查：批准访问 A 网站，不等于把 GitHub Token 交给它，发错端点会以 credential_endpoint_mismatch 拒绝。

### ⑥ 补权限：拒绝→提案→人批准

Agent 装依赖被拦，OpenShell 从拦截记录里起草最小规则（限定到程序+主机+端口），人在宿主机确认，热加载生效、不用重启。也可开 Policy Advisor 让 Agent 自己提案，但默认关闭、默认等人工审核。

### ⑦ 校验：自动查"这个口子开得危险不"

新增规则交给 Policy Prover（SMT 求解器）分析，例如有没有"带着凭据访问新目的地"的能力，并标记私有地址、通配主机。注意：**这只验证策略本身，不验证 Agent 写出的代码对不对。**

### ⑧ 边界：它不是万能保险箱

原始 TLS 隧道不做凭据替换；你自己塞进文件/提示词的密钥它管不了；请求批准发给云端模型后，内容照样到达模型服务商——**沙箱管的是权限，不是把云推理变本地推理。**

## 三、现实行动指南：怎么塞进你的工作流

### ① 先做"空沙箱"验证，别一上来接真实仓库

按官方三步跑通：安装 → `openshell status` 确认 Status: Connected + Authentication: Authenticated → `sandbox create --name demo`。默认镜像不带 Agent CLI，空沙箱是正常的。拿一个无敏感数据的小项目验证三件事：工具能不能跑、网络规则够不够、被拒的请求好不好判断。

### ② 把"最小权限"写成策略，而不是事后补救

接入日常仓库前，先明确列出：这个 Agent 能读哪些目录、能写哪些目录、能连哪几个域名。文件策略记得改成 hard_requirement，否则规则失效时它静默放行，你以为锁着，其实没锁。

### ③ 密钥一律走 Provider，禁止进环境变量

任何 API Key 都配进 Provider，让 Agent 只拿占位令牌。项目文件、提示词里出现过的旧密钥视为已泄露，该轮换就轮换。这是收益最大、成本最低的一步。

### ④ 保留人工审批，至少跑满一个观察周期

别开自动批准。先用小任务观察"它到底申请了哪些权限"——看到具体哪个程序要访问哪里，比面对一句笼统的"允许所有操作"好判断得多。等你对它的权限画像有了底，再考虑放开不涉及凭据的公网访问。

### ⑤ 把 Agent 的输出当"草稿"，不是"成品"

文件限制正常生效，你开放的可写目录仍可能被它改错。代码审查、测试、版本管理该做的还得做，**OpenShell 解决的是"越权"，不是"写错"。**

### ⑥ 团队推广的顺序

个人先跑通 → 沉淀一份可复用的策略模板（文件白名单 + 域名白名单 + Provider 凭据）→ 再给团队的 Agent 统一套上。想上 K8s 的话，先确认集群网络插件真的执行 NetworkPolicy，否则规则只是写在纸上。

## 一句话决策点

**如果你已经开始让 Agent 碰真实代码库、真实密钥，OpenShell 值得花半天跑通；如果你还在让 Agent 写独立小脚本，当前的收益不抵学习成本。**
